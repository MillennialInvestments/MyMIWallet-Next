# ChatGPT Memory Ingestion (Four-Pillar System)

This folder is the **secondary source of truth** for conversations exported from ChatGPT. It is deliberately read-only for humans and is regenerated by the `chatgpt_memory_ingestor` n8n workflow. The goal is to provide institutional memory without replaying old conversations, while keeping CI4 code and docs as the primary authority.

## Directory layout

```
docs/chatgpt/
├─ raw/
│  └─ data.json                 # Monthly ChatGPT export (overwritten)
├─ processed/
│  ├─ index.json                # Knowledge index of all conversations
│  ├─ completed.json            # Completed/closed threads
│  ├─ unresolved.json           # Threads that still need action
│  ├─ unresolved.md             # Human-friendly unresolved summaries
│  ├─ recurring_topics.json     # Recurring themes across months
│  └─ last_ingest.meta.json     # Hashes + timestamps of the last run
├─ diffs/
│  └─ new_since_last_run.md     # Human diff of what’s new since the prior ingest
└─ README.md
```

Existing legacy files under `docs/chatgpt/` remain for historical reference; the files above are the authoritative outputs for the Four-Pillar system.

## Monthly human workflow

1. Download your ChatGPT export from the account portal.
2. Overwrite `docs/chatgpt/raw/data.json` with the new export.
3. Trigger the `chatgpt_memory_ingestor` n8n workflow (manually or via the scheduled nightly scan).
4. Review `docs/chatgpt/diffs/new_since_last_run.md` to see what is new and needs attention.

No other manual steps are required.

## n8n processing contract

- **Workflow name:** `chatgpt_memory_ingestor`
- **Inputs:** `docs/chatgpt/raw/data.json`, `docs/chatgpt/processed/last_ingest.meta.json`
- **Hashing:** Each conversation is hashed from its title, first user message, and timestamps to identify duplicates.
- **Classification:** Every conversation is labeled as `completed`, `unresolved`, `recurring`, or `new` based on comparison with the last ingest and detected closure status.
- **Outputs:**
  - `docs/chatgpt/processed/index.json` — knowledge index (id, tags, status, related modules, last activity).
  - `docs/chatgpt/processed/completed.json` — ledger of completed threads to prevent rework.
  - `docs/chatgpt/processed/unresolved.json` and `docs/chatgpt/processed/unresolved.md` — open items with what was attempted, what is missing, and the next system to handle them.
  - `docs/chatgpt/processed/recurring_topics.json` — recurring pain points or themes.
  - `docs/chatgpt/processed/last_ingest.meta.json` — source hash, timestamps, conversation count.
  - `docs/chatgpt/diffs/new_since_last_run.md` — **primary human diff** showing what changed since the last export.

## How the pillars consume this data

- **n8n** uses the processed files to avoid duplicate suggestions, detect repeated pain points, and adjust priorities.
- **Codex** reads only the processed `.md` and `.json` outputs to validate history and avoid re-implementing past attempts.
- **ChatGPT** (Plus) relies on the processed outputs to ground future reasoning without replaying historical context.
- **chat.mymiwallet.com** surfaces quick answers (e.g., "what’s unresolved?") by reading the processed files.

## Guardrails

- Do not hand-edit files under `processed/` or `diffs/`; they are overwritten by the workflow.
- Keep `raw/data.json` limited to the official monthly export and avoid embedding secrets.
- CI4 code and docs remain the primary source of truth; this folder is a secondary memory to prevent drift.
