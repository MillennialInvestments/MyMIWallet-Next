✅ STEP 2 — PROJECT INVENTORY (NO OPINIONS, NO MERGING)

Perform a full inventory of THIS project.

Identify and list EVERYTHING that exists or is implied in THIS project, including:
1) The project’s purpose and long-term goal
2) Core systems or modules (even if only described)
3) Data sources (APIs, files, databases)
4) Automation workflows (CRON, scripts, pipelines)
5) UI or user-facing components
6) Background services or jobs
7) Security, logging, and monitoring mechanisms
8) Known bugs, technical debt, or blockers
9) Planned features or roadmap items (ONLY if mentioned or implied here)
10) External integrations (APIs, platforms, tools)

Rules:
- Do NOT summarize, judge, or prioritize.
- Do NOT merge items unless they are provably identical.
- If something is referenced as required for the system to function, include it even if not implemented.
- If a referenced item is ambiguous, include it as “Implied” and name what evidence exists in THIS project.

Output format:
- Use clear headers
- Use bullet lists
- Include “Status: Active | Planned | Deprecated | Blocked | Implied” for each item
- Include “Primary Files/Modules” if known; otherwise “Unknown (not specified in project)”
