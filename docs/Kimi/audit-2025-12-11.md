# Kimi-K2 Integration Audit (2025-12-11)

## Summary
- Kimi toggle lives in `app/Config/SiteSettings.php` via `enableKimiK2` with `.env` override `AI_ENABLE_KIMI_K2`.
- Helper `ai_helper.php` exposes `aiKimiEnabled()` and is autoloaded.
- Kimi client available through `App\Libraries\KimiClient` enforcing toggle and API key.
- Advisor dashboard view (`app/Modules/Advisor/Views/advisor_dashboard.php`) respects toggle.

## Located Files
- Config: `app/Config/SiteSettings.php`, `app/Config/Kimi.php`, helper `app/Helpers/ai_helper.php`.
- Client: `app/Libraries/KimiClient.php`.
- Advisor UI: `app/Modules/Advisor/Views/advisor_dashboard.php`.
- Docs: `docs/kimi-k2-integration.md`.

## Routes & Modules Using Kimi
- API guards in `MarketingController`, `ManagementController`, `AIController`, `AdvisorController` via `_remap` + `aiKimiEnabled()`.
- Marketing and Alerts endpoints now expose Kimi generators (`/Marketing/generateKimiSummaries`, `/Marketing/generateKimiPosts`, `/Alerts/generateAlertCommentary/{id}`, `/Alerts/generateAlertSocialCopy/{id}`).
- Advisor routes `/Advisor/generateInsight`, `/Advisor/generateStoryboard`, `/Advisor/tradeAnalysis/{id}` remain toggle-protected.

## Gaps / TODOs
- Add richer error handling and schema validation on Kimi responses.
- Persist generated Kimi marketing outputs for reuse (current endpoints return JSON only).
- Consider middleware-level guard for all `/API/*` Kimi routes.
- Expand Advisor module beyond view skeleton (controller/actions not yet audited in depth).
