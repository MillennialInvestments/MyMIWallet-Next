# AIOps Form QA Subsystem Review (2026-02-25)

## Scope
- Migration: `CreateAiOpsFormTests`
- Model: `FormTestModel`
- Services: `FormIntelligenceService`, `FormTestExecutor`, `FormPatchPlanner`
- Command: `FormTestScan`
- Console registration and form-test docs

## Verified
- Required files are present in expected PSR-4 directories.
- Namespaces and command registration for form-test components are correctly cased.
- `mapRouteToController()` supports exact, regex token, and fuzzy fallback route matching.
- `generatePayload()` skips CSRF-like fields and avoids empty payloads.
- HTTP submitter applies method-aware request options and trims response body.
- Patch planner trims response/log snapshots and shell-escapes ingest command arguments.

## Issues Found
1. Environment-level blocker prevented DB-connected runtime validation:
   - `php spark migrate:refresh --all` failed to connect to MySQL in this environment.
   - `php spark aiops:form:test --url="/Budget/Account-Manager" --no-ingest` failed at insert stage for the same reason.

2. Potential false positives in `detectError()` from broad patterns:
   - The `error -` signal may match benign text in logs/responses.

3. Markdown injection risk in generated patch jobs:
   - `source_value`, `action`, `headers`, and body snippets are interpolated directly into markdown without escaping/fencing.

## Recommended follow-up
- Add an optional `--dry-run` mode to skip DB writes and HTTP submission while validating analysis/mapping.
- Add stricter route matcher prioritization by method + route collection order.
- Escape or fence user-sourced markdown fields before writing patch jobs.
- Add tests for payload generation and error detection heuristics.
