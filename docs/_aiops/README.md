# AIOps Workflow Outputs

This folder holds the outputs generated by n8n workflows for MyMI Wallet. To keep access safe and predictable, n8n should only read and write inside `~/mymiwallet/site/current/` and persist workflow outputs under `~/mymiwallet/site/current/docs/`.

## Directory layout
- `docs/_aiops/inventory/` – inventory reports such as `docs_inventory.md` and per-subdirectory inventories.
- `docs/_aiops/reports/` – routine reports (module maps, static analysis digests, security audit summaries, PR readiness checks, etc.).
- `docs/_aiops/diffs/` – suggested patch proposals that Codex can later apply to the repository.
- `docs/_aiops/next-steps/` – generated next-step plans for each docs subdirectory or security follow-ups.

Use these folders as the canonical pipeline for "n8n generates → Codex applies" automation. Each workflow should write its artifacts into the appropriate subfolder to keep outputs organized and reviewable.

## Manual Priority Integration

Manual error-driven priorities are managed under `docs/_aiops/manual/` and are consumed by AIOPS before any automated fix cycle starts.

- Actionable tasks: `docs/_aiops/manual/priorities/`
- Error input stream: `docs/_aiops/error-input/`
- State tracking: `docs/_aiops/aiops-state/`
- Notification config: `docs/_aiops/notifications/channels.json`

If no current error signature maps to a manual priority item, AIOPS must not open a PR.

# AI-Ops Governance (Worker-Only Mode)
> This folder is auto-generated. Do not edit manually.

## Purpose
AI-Ops is a worker. It produces reports and safe suggestions.
It does not make decisions, rewrite architecture, or change business logic.

## Inputs
- /docs/**/*.md
- app/Modules/**
- app/Controllers/**
- app/Libraries/**
- Spark command outputs

## Triggers
- Nightly schedule (n8n Cron)
- Optional manual run: `php aiops/aiops_worker.php --mode=manual`

## Outputs (Auto-generated)
- doc-change-log.md — doc file change detection
- gap-report.md — heuristic mismatch report (docs vs code)
- stale-docs.md — docs older than threshold
- next-steps.md — suggestions, **DOC ONLY / LOW RISK / TESTING**
- spark-results.md — whitelisted spark command summaries
- ci-summary.md — CI summary (optional integration)
- nightly-summary.md — single pane summary for humans

## Safety Rules (Hard)
AI-Ops MAY:
- report
- summarize
- propose doc updates
- propose low-risk refactors (<50 LOC)
- propose missing tests
- propose logging improvements

AI-Ops MAY NOT:
- redesign system architecture
- rename modules/routes
- add dependencies
- change business logic
- run non-whitelisted commands

## Human Workflow
1) Read nightly-summary.md
2) Pick 1–3 items from next-steps.md
3) Implement via human + ChatGPT (Codex optional)
4) Re-run AI-Ops
